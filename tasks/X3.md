## Task

Once the drawn route is complete (`canPlay`), a **Preview** button (👁, `preview.button`) appears in the planning bottom bar next to PLAY. On tap, the plan replays in fast ghost mode (the "dotted arc"): the ghost thief advances along the route and, at each tick, the guards/cameras/lasers **and their cones** (`yapGhostCones`, exactly `visibleCells` for that tick) are drawn at that tick, at reduced opacity — the same visual language as the C6 ghost (`YAP_GHOST_ALPHA`). At the end (win or caught), automatic return to planning: route kept, PLAY still available. One tap during the preview ends it early. Flag `?flag=preview:0/1`, default ON.

Layout note: on a 360 px viewport the bottom row is Clear | Hint | Preview | PLAY; the Preview button is 80 px (`👁 Preview` at 14 px) so PLAY keeps its known tap geometry on every viewport; when the route is complete, Preview takes the slot next to PLAY and the Hint button yields for that moment (its revealed ghost stays drawn on the board).

## Acceptance criteria

- `yapPreviewStates(level, plan)` (pure, in `ghost.ts`, via `resolveTick` only): one state per tick of the plan — `length == plan.length`; the last state of a plan that runs to its end carries exactly the outcome of `run(level, plan)`; past a detection the chain keeps advancing (same rule as `YapGhostPreview.yapAt`) and the caught tick carries the run outcome. Unit-tested in `tests/unit/preview.test.ts` (win plan, caught plan, cones == `visibleCells`, flag parsing, ghost layer cleared in preview mode, preview speed > playback speed).
- Preview button visible only when `canPlay` and the flag is on; during the preview the bottom bar shows `preview.running` and the top bar the tick counter; at the end (or on tap) back to planning with the route kept and PLAY available.
- i18n: `preview.button` / `preview.running` in FR and EN, appended at end of the dictionaries.
- Full local check green: `npm run typecheck && npm run lint && npm run test && npm run validate && npm run build`.
